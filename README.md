# TutorTrack

一个记录家教课时、管理学生、自动计算收入，并支持日历视图、收入图表和 JSON 备份恢复的网页应用。

- 纯 HTML + CSS + 原生 JavaScript，没有框架、没有构建步骤。
- 数据保存在浏览器 `localStorage` 中，不上传到任何服务器。
- 双击 `index.html` 即可使用（推荐 Chrome / Edge）。

---

## 功能

- **学生管理**：添加、编辑、删除学生；每位学生包含昵称、年级、科目、默认时薪。
- 在「记一节课」中从下拉框选择学生，自动带出该学生的默认时薪，仍可手动修改。
- 删除学生时**保留全部历史课程记录**，收入和统计不受影响。
- 添加课程：上课日期、课程时长、每小时课时费。
- 课时费输入框使用上 / 下箭头时每次增减 10 元，并保留已输入的零头（例如 134 → 144 → 134）；手动输入任意金额不受影响。
- **收款管理**：每条课程记录都有「待收款 / 已收款」状态，新记录默认待收款，可随时一键切换。
- **编辑课程记录**：在列表中点击「编辑」，可修改学生、上课日期、时长、课时费和收款状态；保存后原地更新，不会新增重复记录。
- 自动计算每节课收入：`时长(分钟) ÷ 60 × 课时费`。
- 实时预览本节课收入。
- 查看课程记录列表（按日期从新到旧），每行显示收款状态。
- **日历视图**：在「列表视图 / 日历视图」之间切换；支持上个月、下个月、今天；完整 6×7 月历；有课程的日期显示节数和收入；点击日期查看当天学生、时长、收入、收款状态，并可直接切换收款、编辑或删除。
- **收入分析**：
  - 月度收入趋势柱状图，默认当前年份，可切换年份；没有课程的月份显示为 0。
  - 应收 / 已收 / 待收统计卡片和占比条，满足「应收 = 已收 + 待收」。
  - 学生收入排行，支持按月 / 按年查看，默认从高到低；已删除学生的历史收入仍然保留。
- **月度账目**：
  - 可按月份查看授课节数、总时长、应收、已收、未收和实际收入较上月的变化。
  - 月度课程明细支持按学生姓名、科目和收款状态筛选，并显示日期、学生、科目、时长、课时费、金额和收款状态。
  - 未收款项单独汇总，按上课日期从早到晚排列，可直接标记收款；误操作后可在提示中撤销。
  - 「导出本月账目」生成 UTF-8 CSV，包含月度汇总和该月全部课程明细，可用 Excel 打开；导出不受当前筛选影响。
- **多语言界面**：右上角可在「简体中文 / 繁體中文 / English」之间即时切换，无需刷新；语言选择单独保存在 `tutortrack:lang`，不会修改学生、课程或备份数据。
- **数据管理**：
  - 「导出备份」将全部学生和课程记录导出为 `TutorTrack-backup-YYYY-MM-DD.json`，导出不会修改当前数据。如果正式数据加载失败或缓存不可信，标准备份会被拒绝，避免导出空数据。
- 在只读或加载失败状态会显示「导出原始恢复文件」，直接下载 `tutortrack:v1` 的原始字符串为 `TutorTrack-raw-YYYY-MM-DD.json`；它不经过解析或修正，不是标准备份，当前版本不保证能直接导入。
  - 「导入备份」会先校验文件格式和必填字段，再显示学生数、课程数和覆盖警告；取消或校验失败都不会修改数据。
  - 导入采用整体替换，同一份备份重复导入不会产生重复记录；写入成功后才更新页面，刷新后数据仍在。
- 删除课程记录（带二次确认）。
- 统计应收、已收、待收、授课节数、总时长，可在「按月 / 全年」之间切换，并可选择具体月份。
- 所有统计都按课程的**上课日期**归属，与记录创建时间无关。
- 刷新页面后数据仍然保留。
- 手机和电脑端均使用同一套响应式布局，未引入任何前端框架或图表库。

**暂不支持**：账号登录、云同步、在线支付、AI。

## 多语言

支持三种界面语言，默认简体中文：

- 简体中文（`zh-CN`）
- 繁體中文（`zh-TW`）
- English（`en`）

切换语言后会立即更新静态文案、动态列表、日历、图表、提示和日期 / 金额格式，不会重新加载页面。语言选择保存在独立的 `tutortrack:lang` 键中，刷新后继续生效；切换语言不会写入或重置 `tutortrack:v1`，也不会改变备份文件结构。货币始终为人民币（¥），不会因语言切换而换算。

翻译文案集中在 `js/i18n.js`，通过统一的 `I18N.t('key')` 读取；缺失键会回退到简体中文，再回退到键名，不会显示 `undefined`。

## 数据说明

- 存储键：`tutortrack:v1`（键名保留 v1 是为了兼容第一版数据，内部结构已升级为 version 4）
- 语言键：`tutortrack:lang`（`zh-CN` / `zh-TW` / `en`），与业务数据完全分开
- localStorage 外层还包含 `revision`、`updatedAt`、`writerId`，用于多标签页一致性；备份文件**不会**导出这些内部字段
- **金额单位**：正式存储、计算和备份中的金额统一使用整数分（`hourlyRateCents` / `feeCents`）；用户输入和界面展示使用元。1 元 = 100 分，12.50 元 = 1250 分
- 读取能力和写入能力分别检测：先读取 `tutortrack:v1`，再使用独立临时 key 探测写入；写入探测不会使用或覆盖正式数据 KEY
- 如果已有数据可以读取，但 localStorage 满额或不可写，应用会正常展示学生、课程、统计、日历和图表，并进入只读模式；导出仍然可用，普通写操作返回 `WRITE_BLOCKED`
- 如果 `getItem()` 抛出异常，不会被当作“没有数据”；会显示存储不可访问提示并保留原始数据
- 数据迁移使用 `schemaVersion` 标记。迁移前会把原始内容保存到 `tutortrack:v1:pre-migrate:vN`，迁移失败时保留原始 `tutortrack:v1` 并进入只读状态，避免覆盖
- 迁移会校验学生/课程 ID、字段、数量、时长、收款状态和金额；遇到未知字段、重复 ID、未来版本或缺失必需字段时停止迁移并报告
- 多标签页：其他标签页写入后会通过 `storage` 事件自动刷新；支持的浏览器使用 Web Locks 串行化写入，不支持时依赖 revision 做尽力而为的冲突检测。新增记录可在最新数据上安全重放；编辑/删除的目标记录被其他标签页修改时返回冲突并保留当前表单。
- 普通业务写入采用「构造候选数据 → 序列化 → 写入 localStorage → 回读验证 → 提交内存和 revision」。写入失败时正式内存、revision 和 UI 均不变，表单输入保留。
- 写入错误会区分存储空间不足、存储不可用、写入失败、revision 冲突、校验失败、只读状态和序列化失败。
- 数据结构：

```json
{
  "version": 4,
  "schemaVersion": 4,
  "revision": 12,
  "updatedAt": 1762156800000,
  "writerId": "tab_xxx",
  "students": [
    {
      "id": "s_xxx",
      "name": "小明",
      "grade": "初二",
      "subject": "数学",
      "hourlyRateCents": 12000,
      "createdAt": 1762156800000
    }
  ],
  "lessons": [
    {
      "id": "l_xxx",
      "studentId": "s_xxx",
      "student": "小明",
      "date": "2026-11-03",
      "duration": 90,
      "hourlyRateCents": 12000,
      "feeCents": 18000,
      "paid": false,
      "createdAt": 1762156800000
    }
  ]
}
```

- `duration`：分钟，整数。
- `hourlyRateCents`：时薪，整数分。学生档案里是默认时薪，课程记录里是上课时的时薪快照。
- `feeCents`：这一节课的费用，整数分。新增或编辑课程时按 `Math.round(hourlyRateCents × duration ÷ 60)` 的整数余数算法计算（`floor(n/60) + (n%60 ≥ 30 ? 1 : 0)`），不使用浮点中间结果；汇总时只对整数分求和。计算前会校验时薪、时长，乘积超出安全整数范围时拒绝写入。历史课程优先使用已保存的 `feeCents`，不会因修改学生默认时薪而变化。加载和导入 v4 数据时会校验费用是否接近按课程时薪快照和时长计算的结果，容差为 `Math.ceil(duration / 120) + 1` 分，用于兼容历史时薪舍入差异。
- 新数据的业务边界：学生默认时薪和课程时薪为 0–1,000,000 分（0–10,000 元），课程时长为 1–1440 整数分钟，课程费用不超过 24,000,000 分。已有历史记录在 `duration` / `hourlyRateCents` / `feeCents` 均未变化时保留原值；一旦修改任一计费字段，就必须满足新边界。编辑历史课程只改日期、学生关联、昵称或收款状态时，不会重算历史费用。
- 课程时长必须是整数，不再使用 `Math.round()` 自动修正小数；`30.5`、`NaN`、`Infinity`、0 和负数都会被拒绝。
- 编辑历史超限记录时，金额是否修改按转换后的整数分比较，而不是按输入框字符串比较；`20000` 与 `20000.00` 视为同一金额，`20000.01` 视为已修改并重新执行上限校验。
- 编辑课程时，只有 `duration` 或 `hourlyRateCents` 变化才会重新计算 `feeCents`；只修改日期、学生关联、昵称快照或收款状态时保留原费用。修改学生关联不会把该学生当前的默认时薪写入历史课程的时薪快照。
- `date`：`YYYY-MM-DD` 字符串。判断“是否本月/本年”时直接比较前 7 位 / 前 4 位，不做日期解析，避免时区问题。
- `paid`：布尔值。`false` 表示待收款，`true` 表示已收款；**旧记录没有该字段时按 `false` 处理**。
- `lessons[].studentId`：指向学生档案；`lessons[].student` 是昵称快照，用于学生被删除后继续显示。
- 编辑课程时会原地更新同一条记录，`id` 和 `createdAt` 保持不变。
- 学生改名时，会同步刷新其课程的昵称快照；修改默认时薪**不会**影响历史课程的收入。
- 旧版本迁移：v1（纯课程数组）会自动根据课程昵称生成学生档案并补 ID；v2 会补 `paid: false`；v1 / v2 / v3 的元金额都会一次性转换为整数分。旧时薪会解析为精确十进制分数，再用整数比例计算历史费用，不会先把时薪四舍五入成整数分后重算；迁移前会保存 `tutortrack:v1:pre-migrate:vN` 快照，校验数量、ID、日期、时长、收款状态和每节课金额一致后才写回 v4。
- 迁移只会在 `schemaVersion < 4` 时执行；已经是 v4 的数据不会再次乘以 100。迁移失败时原始 `tutortrack:v1` 保留，应用进入只读状态并提示。
- JSON 数据损坏时，原始内容会保留在 `tutortrack:v1`，并尽力复制到 `tutortrack:v1:broken:<时间戳>`；不会自动重置为空列表。broken 快照最多保留最近 3 份。
- 导入前，如果 localStorage 中已有正式数据，会先把原始内容完整保存到 `tutortrack:v1:pre-restore:<时间戳>`，并回读确认与原内容完全一致。快照写入、回读失败或同名快照键已存在时**取消导入**，正式数据不会被修改。当前没有正式数据（首次导入）时不需要快照。同名键冲突时不会覆盖旧快照，也不会换键继续。
- 自动快照保留策略：`pre-restore` 最多 5 份，`broken` 最多 3 份，两类自动快照合计容量预算 2 MiB。容量按 `(键长度 + 值长度) × 2` 的 UTF-16 粗估，不包含浏览器内部开销，也不代表浏览器真实配额。
- 清理按时间戳从旧到新进行，只删除严格匹配 `pre-restore:<数字>` 或 `broken:<数字>` 的键；`pre-migrate` 快照和相似前缀键永远不参与自动清理。每种类型至少保留最近一份可读快照。若清理后仍无法满足容量预算，恢复导入会失败，损坏数据加载则不会创建 broken 副本，但原始 `tutortrack:v1` 始终保留。

### 备份文件格式

导出的 JSON 结构如下（`backupVersion: 2` 起明确标记 `amountUnit: "cent"`，`hourlyRateCents` 和 `feeCents` 都是整数分）：

```json
{
  "app": "TutorTrack",
  "backupVersion": 2,
  "dataVersion": 4,
  "amountUnit": "cent",
  "exportedAt": "2026-11-03T10:00:00.000Z",
  "counts": { "students": 1, "lessons": 2 },
  "students": [],
  "lessons": [
    {
      "id": "l_xxx",
      "studentId": "s_xxx",
      "student": "小明",
      "date": "2026-11-03",
      "duration": 90,
      "hourlyRateCents": 12000,
      "feeCents": 18000,
      "paid": false,
      "createdAt": 1762156800000
    }
  ]
}
```

导入时会校验 `app`、`backupVersion`、`dataVersion`、`amountUnit`、`students`、`lessons`，以及学生 / 课程的 `id` 是否唯一、日期、时长、金额和收款状态是否合法。

- `dataVersion >= 4` 的备份必须带 `amountUnit: "cent"`，金额字段按整数分读取，**不会再次乘以 100**。
- `dataVersion 1–3` 的旧备份按“元”读取（`rate`），导入时转换为整数分，并使用旧公式保留每节历史课程费用。
- 旧备份缺少 `paid` 字段时按「待收款」处理；新备份缺少 `feeCents` 或金额不是整数分时会被拒绝，不会静默修正。

3. 可以看到 `tutortrack:v1` 的内容。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面白屏 / 没有数据 | JS 报错 | F12 → Console 查看红色错误 |
| 刷新后数据消失 | 更换了打开方式（`file://` ↔ `localhost`），或使用无痕模式 | 固定一种打开方式 |
| 输入中文按回车误提交 | 输入法组合状态 | 先按空格或 Esc 结束输入，或点击按钮提交 |
| 金额显示异常 | 浮点误差 | 本项目已按“分”累加并保留两位小数 |
| 删除后统计没变 | 不应发生 | 所有增删都统一走 `render()`；若出现请记录复现步骤 |
| 删除学生后课程还在吗 | 这是设计行为 | 会保留；课程使用昵称快照继续显示和统计 |
| 改学生名字后历史课程变了吗 | 会同步刷新昵称 | 只改显示名，不改历史课时费和收入 |
| 导入备份会合并数据吗 | 不会 | 采用整体替换；同一份备份导入多次也不会重复 |
| 导入失败会清空数据吗 | 不会 | 先校验再写入，写入成功后才替换页面数据 |
| 是否引入了图表库 | 没有 | 图表使用原生 HTML / CSS 绘制，无第三方依赖 |
