# TutorTrack

一个记录家教课时、管理学生、自动计算收入，并支持日历视图、收入图表和 JSON 备份恢复的网页应用。

- 纯 HTML + CSS + 原生 JavaScript，没有框架、没有构建步骤。
- 数据保存在浏览器 `localStorage` 中，不上传到任何服务器。
- 双击 `index.html` 即可使用（推荐 Chrome / Edge）。

---

## 功能

- **学生管理**：添加、编辑、删除学生；每位学生包含昵称、年级、科目、默认时薪。
- 在「记一节课」中从下拉框选择学生，自动带出该学生的默认时薪，仍可手动修改。
- 删除学生时**保留全部历史课程记录**，收入和统计不受影响。
- 添加课程：上课日期、课程时长、每小时课时费。
- 课时费输入框使用上 / 下箭头时每次增减 10 元，并保留已输入的零头（例如 134 → 144 → 134）；手动输入任意金额不受影响。
- **收款管理**：每条课程记录都有「待收款 / 已收款」状态，新记录默认待收款，可随时一键切换。
- **编辑课程记录**：在列表中点击「编辑」，可修改学生、上课日期、时长、课时费和收款状态；保存后原地更新，不会新增重复记录。
- 自动计算每节课收入：`时长(分钟) ÷ 60 × 课时费`。
- 实时预览本节课收入。
- 查看课程记录列表（按日期从新到旧），每行显示收款状态。
- **日历视图**：在「列表视图 / 日历视图」之间切换；支持上个月、下个月、今天；完整 6×7 月历；有课程的日期显示节数和收入；点击日期查看当天学生、时长、收入、收款状态，并可直接切换收款、编辑或删除。
- **收入分析**：
  - 月度收入趋势柱状图，默认当前年份，可切换年份；没有课程的月份显示为 0。
  - 应收 / 已收 / 待收统计卡片和占比条，满足「应收 = 已收 + 待收」。
  - 学生收入排行，支持按月 / 按年查看，默认从高到低；已删除学生的历史收入仍然保留。
- **多语言界面**：右上角可在「简体中文 / 繁體中文 / English」之间即时切换，无需刷新；语言选择单独保存在 `tutortrack:lang`，不会修改学生、课程或备份数据。
- **数据管理**：
  - 「导出备份」将全部学生和课程记录导出为 `TutorTrack-backup-YYYY-MM-DD.json`，导出不会修改当前数据。
  - 「导入备份」会先校验文件格式和必填字段，再显示学生数、课程数和覆盖警告；取消或校验失败都不会修改数据。
  - 导入采用整体替换，同一份备份重复导入不会产生重复记录；写入成功后才更新页面，刷新后数据仍在。
- 删除课程记录（带二次确认）。
- 统计应收、已收、待收、课程次数、总时长，可在「本月 / 全年」之间切换。
- 所有统计都按课程的**上课日期**归属，与记录创建时间无关。
- 刷新页面后数据仍然保留。
- 手机和电脑端均使用同一套响应式布局，未引入任何前端框架或图表库。

**暂不支持**：账号登录、云同步、在线支付、AI。

## 多语言

支持三种界面语言，默认简体中文：

- 简体中文（`zh-CN`）
- 繁體中文（`zh-TW`）
- English（`en`）

切换语言后会立即更新静态文案、动态列表、日历、图表、提示和日期 / 金额格式，不会重新加载页面。语言选择保存在独立的 `tutortrack:lang` 键中，刷新后继续生效；切换语言不会写入或重置 `tutortrack:v1`，也不会改变备份文件结构。货币始终为人民币（¥），不会因语言切换而换算。

翻译文案集中在 `js/i18n.js`，通过统一的 `I18N.t('key')` 读取；缺失键会回退到简体中文，再回退到键名，不会显示 `undefined`。

## 数据说明

- 存储键：`tutortrack:v1`（键名保留 v1 是为了兼容第一版数据，内部结构已升级为 version 3）
- 语言键：`tutortrack:lang`（`zh-CN` / `zh-TW` / `en`），与业务数据完全分开
- 数据结构：

```json
{
  "version": 3,
  "students": [
    {
      "id": "s_xxx",
      "name": "小明",
      "grade": "初二",
      "subject": "数学",
      "rate": 120,
      "createdAt": 1762156800000
    }
  ],
  "lessons": [
    {
      "id": "l_xxx",
      "studentId": "s_xxx",
      "student": "小明",
      "date": "2026-11-03",
      "duration": 90,
      "rate": 120,
      "paid": false,
      "createdAt": 1762156800000
    }
  ]
}
```

- `duration`：分钟，整数。
- `rate`：元/小时，可带小数。
- `date`：`YYYY-MM-DD` 字符串。判断“是否本月/本年”时直接比较前 7 位 / 前 4 位，不做日期解析，避免时区问题。
- `paid`：布尔值。`false` 表示待收款，`true` 表示已收款；**旧记录没有该字段时按 `false` 处理**。
- `lessons[].studentId`：指向学生档案；`lessons[].student` 是昵称快照，用于学生被删除后继续显示。
- 编辑课程时会原地更新同一条记录，`id` 和 `createdAt` 保持不变。
- 学生改名时，会同步刷新其课程的昵称快照；修改默认时薪**不会**影响历史课程的收入。
- 如果打开的是第一版的旧数据，会自动根据课程昵称生成学生档案；第二版数据会自动补上 `paid: false`。迁移后会立刻写回 v3 结构，不需要手动操作，也不会清空任何旧记录。
- 数据损坏时，原始内容会备份到 `tutortrack:v1:broken:<时间戳>`，然后重置为空列表。
- 每次导入前，原来的完整数据会尽力备份到 `tutortrack:v1:pre-restore:<时间戳>`；如果导入写入失败，当前数据不会被替换。

### 备份文件格式

导出的 JSON 结构如下（`income` 只是导出时计算出来的展示字段，不会写回内部数据）：

```json
{
  "app": "TutorTrack",
  "backupVersion": 1,
  "dataVersion": 3,
  "exportedAt": "2026-11-03T10:00:00.000Z",
  "counts": { "students": 1, "lessons": 2 },
  "students": [],
  "lessons": [
    {
      "id": "l_xxx",
      "studentId": "s_xxx",
      "student": "小明",
      "date": "2026-11-03",
      "duration": 90,
      "rate": 120,
      "paid": false,
      "income": 180,
      "createdAt": 1762156800000
    }
  ]
}
```

导入时会校验 `app`、`backupVersion`、`dataVersion`、`students`、`lessons`，以及学生 / 课程的 `id` 是否唯一、日期、时长、课时费和收款状态是否合法。缺少 `paid` 的旧备份会按「待收款」处理。

### 查看 / 清空数据

1. 按 `F12` 打开开发者工具。
2. 进入 **Application（应用）→ Local Storage**。
3. 可以看到 `tutortrack:v1` 的内容。
4. 右键删除该项即可清空所有记录（不可恢复）。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面白屏 / 没有数据 | JS 报错 | F12 → Console 查看红色错误 |
| 刷新后数据消失 | 更换了打开方式（`file://` ↔ `localhost`），或使用无痕模式 | 固定一种打开方式 |
| 输入中文按回车误提交 | 输入法组合状态 | 先按空格或 Esc 结束输入，或点击按钮提交 |
| 金额显示异常 | 浮点误差 | 本项目已按“分”累加并保留两位小数 |
| 删除后统计没变 | 不应发生 | 所有增删都统一走 `render()`；若出现请记录复现步骤 |
| 删除学生后课程还在吗 | 这是设计行为 | 会保留；课程使用昵称快照继续显示和统计 |
| 改学生名字后历史课程变了吗 | 会同步刷新昵称 | 只改显示名，不改历史课时费和收入 |
| 导入备份会合并数据吗 | 不会 | 采用整体替换；同一份备份导入多次也不会重复 |
| 导入失败会清空数据吗 | 不会 | 先校验再写入，写入成功后才替换页面数据 |
| 是否引入了图表库 | 没有 | 图表使用原生 HTML / CSS 绘制，无第三方依赖 |
